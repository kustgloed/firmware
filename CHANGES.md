# Changes from upstream

The base is the upstream **development snapshot 17.0.0-devV5**, pinned to
`3cdb5108b924ec26dec81d2c92962b70b185bd01`. It precedes an upstream release.

| Path | Reason |
| --- | --- |
| `usermods/kite_wind/` | Adds the wind map usermod, controller setup notes, and file licence notices. |
| `tools/kite-wind-access-test.cpp` | Checks the access rules: secret formats, lockout, unlock session, serial payload, device state, local endpoint policy, and the station form field whitelist. Checks the mode record, the access point and station rules per state, setup commit timing, and the factory handoff, setup commit and physical recovery transitions, including power loss at every write, one-off clear and erase failures, and repeated reboots, and the hold-and-release gesture with debounce, re-arming after a failed action and latching after success. Checks the verified temporary-file replacement (lost contents and failed rename keep the old record), when clearing rewrites files, the setup commit back-off, the protected file names including non-canonical paths, and which network entries count as loaded (a password left only in the protected file). Checks the USB factory rules: identity write and finish per mode, the unreadable mode record (refused everywhere, no transition writes), PIN lockout over serial, same-identity recovery, the finish payload, the declared RPC length and the widest payload size. Checks that UDP listeners and serial input other than Improv are allowed in factory state only, and that Improv passes the serial check in every state. |
| `tools/kite-wind-cert-test.cpp` | Checks the certificate date rules: date conversion, inclusive validity, the clock floor, the chain walk up to the trust anchor, the session gate (no bytes to a rejected peer, also after a reconnect), the anchor constants against the compiled-in root, and that the root does not end within 18 months; an implausible `SOURCE_DATE_EPOCH` fails the test. |

| `VERSION` | Holds the firmware release number. |
| `tools/kite_version.py` | Defines the firmware version from `VERSION`, the short commit (or `KITE_FW_COMMIT` when the checkout has no commit) and the build environment, and fails the build on an invalid value. Defines the build epoch for the certificate clock floor from `SOURCE_DATE_EPOCH` or the commit time, and fails the build on an invalid or future value. |
| `wled00/asyncDNS.h` | Holds the lwIP core lock during DNS calls where core locking is enabled. |
| `wled00/cfg.cpp` | Invokes the usermod hooks during protected configuration load and save, and clears the save flag before the write so a change made during a save is not lost. Treats stored secrets that fail their format as unprovisioned, keeps the access point name and password and the update password out of the configuration file (they load from the protected file, and an invalid or missing name counts as unprovisioned), and checks the update password through a lockout. Loads each secret only if it fits without truncation. The PIN lockout is global (single controller). No global unlock flag is reset at load. Loads and writes the lifecycle mode record through a temporary file and rename, and writes the protected file and the configuration file the same way; each temporary file is reopened and checked (size, record or JSON parse) before the rename, because closing a file reports no write error. Keeps setup candidate networks out of storage until the setup commit. Implements the boot resume, setup commit, recovery and handoff requests over this storage, and clears the saved framework station profile on a reset. Clearing the networks resets the DNS server and refreshes the configuration backup so old home networks do not remain there; an ordinary setup boot without loaded networks (no password and no non-default name in any entry) skips that rewrite. Boot removes temporary files left by a cut write before the transitions. A missing or invalid mode record with a complete identity fails closed; the factory USB path recovers it with the current PIN and the same identity, which returns the unit to factory state without clearing its networks. A mode record that exists but cannot be opened or read counts as unreadable and stays closed; it is never treated as a lost record. A sealed mode with an incomplete identity stays closed, and only a full flash erase recovers it. Never formats the filesystem. Writes the factory identity from the USB command, in the mode the command was checked against, through the protected file and the factory mode record, restores the previous values in memory when the write fails, and reloads the stored identity privately (as the boot path and the access point load it) before reporting success. |
| `wled00/fcn_declare.h` | Declares the protected configuration hooks, the PIN check with client address, the update password check, the device state, the local access check, and a result for the settings save. Declares the access point and station gates, the lifecycle transitions, and a write result for the configuration saves. Adds the vendor serial commands for the secret write and the factory finish, and declares the stored mode, the identity check and the verified identity write. |
| `wled00/improv.cpp` | Adds the vendor serial commands that write the per-unit secrets and finish factory provisioning, each with the PIN and lockout, one generic error and a success reply only after a verified write. Requires the stored mode to match the mode loaded at boot. Accepts the USB Wi-Fi command in factory state only, with a matching declared length. Sizes the command buffer for the widest secrets payload, checks the declared payload length, drains an oversize frame and answers it with the same generic error, wipes the buffer on every return and never prints command data. |
| `wled00/kite_access.h` | Adds host-testable access rules for secrets, lockout, unlock session, serial payload, device state, local endpoint policy, and the station form field whitelist. Adds the persisted lifecycle modes with journalled handoff and recovery, the transitions resumed at boot, the access point and station rules per state, and the ten-second hold-and-release recovery gesture. Adds the verified temporary-file replacement, the setup commit back-off and the protected file names for the file handlers. Protected file names fail closed for any path beyond one leading slash, empty names and dot names. Adds the USB factory rules: the identity write and finish gates per mode (an unreadable mode record refuses both and every transition), the serial PIN check with the shared lockout, the finish payload, the declared RPC length check, the widest secrets payload size, and secret buffer wiping. Removes the unused secret-write acceptance rule, which the USB factory rules replace. Adds the factory-only rules for the UDP listeners and for serial input other than Improv, with a per-byte serial check that always admits Improv. |
| `wled00/um_manager.cpp` | Dispatches the protected configuration hooks to enabled usermods. |
| `wled00/set.cpp` | Redacts usermod settings values in debug output. Unlocks per client, no longer saves a PIN, update password, or access point name and password from forms, and checks the update password through a lockout. Authorizes each save before applying it and reports a refused save. The Wi-Fi save applies only station fields and refuses the whole save when any other field (mode, access point, radio, credentials) is submitted; those settings come from the configuration file only. Refuses state changes by text command while the unit is unprovisioned or between lifecycle transitions. Removes the factory reset option of the security page, which formatted the filesystem. |
| `wled00/wled.h` | Removes default secrets, sizes the PIN for eight characters, locks updates by default, and adds the lockout and unlock session state. Removes the global unlock flag. Removes the default access point name and its macro, adds the persisted lifecycle mode, and drops the default-restoring access point start option. |
| `wled00/const.h` | Removes the default access point and update passwords and the fixed PIN retry and timeout constants. |
| `wled00/file.cpp` | Refuses serving the mode record, configuration backups, temporary files and non-flat paths from the filesystem. |
| `wled00/button.cpp` | Replaces the five-second access point and ten-second filesystem format actions on button 0 with the recovery gesture: a hold of at least ten seconds, released while powered, forgets the home networks and reboots into setup. A failed journal write does not reboot and lets the next hold retry. Button 0 no longer fires its preset on the rising edge when all its macros are equal; the preset fires on release. Long-press and repeat actions on button 0 are suppressed. |
| `wled00/util.cpp` | Replaces the PIN check with a per-client check with escalating lockout, and adds an update password check with its own lockout. The PIN lockout is global (single controller), and clients without an IPv4 address never unlock. Derives the device state from the stored identity. Takes the factory, setup and home state from the persisted mode record; a missing, invalid or journalled record fails closed. Exposes the identity completeness check for the USB factory commands. |
| `wled00/wled.cpp` | Expires the unlock session instead of the global PIN flag and stops resetting the access point password to a default. Runs the network update service only for an unlocked client in factory state, and notes it must not be enabled without its own password. Completes a journalled handoff or recovery at boot before any connection, access point or server starts. Starts the access point only in setup mode with the stored identity, keeps it up while a candidate network is tried, and stores the home network durably once the station has an address (after a short window for a phone on the access point) before closing it. A home unit keeps the access point off on outages and timeouts and retries its saved networks. Retries a failed setup commit on the same connection with a bounded back-off instead of reconnecting. The existing filesystem mount formats on mount failure; the result has no identity or mode record and fails closed until factory USB recovery. Opens the UDP sync, realtime, E1.31, DDP and Art-Net listeners only in factory state; the time service keeps its own port. Leaves out the mDNS responder when the build sets `KITE_DISABLE_MDNS`. |
| `wled00/wled_serial.cpp` | Outside factory state, reads only Improv frames and drops the serial JSON, baud rate, version and LED streaming bytes. |
| `wled00/data/settings_pin.htm` | Sizes the PIN entry for eight letters or digits, and sends a PIN entered on the update page to the settings path. |
| `wled00/data/settings_sec.htm` | Removes the PIN field and the set-new-password text; the update password only unlocks the toggles. Removes the factory reset checkbox. |
| `wled00/data/settings_wifi.htm` | Removes the access point name and password fields, and the mode, access point, radio, ESP-NOW, Ethernet and mDNS fields, so the form posts station fields only. |
| `wled00/data/common.js` | Removes the shared development banner. |

| `wled00/data/index.js` | Removes the live-data overlay tied to the previous page. |
| `wled00/data/settings_um.htm` | Removes the global I²C and SPI controls from the usermod settings page. |
| `wled00/data/welcome.htm` | Removes the welcome page development banner. |
| `wled00/wled_server.cpp` | Redirects the root path to settings when the build flag enables it. Passes the client address to the PIN check, uses the PIN lockout for the retry guard, and closes the unlock session on lock. Checks every route, fallback, upload and socket handshake against the device state and client session. Handler filters keep refused requests away from the upload and JSON body callbacks (the library may still parse form fields); uploads start only after the check. Refusals get one plain 403 reply; a wrong PIN and an active lockout share one 401 page. Requires the PIN session and the update password for a firmware update, removes the network bootloader update, settings by URL and the cross-origin headers. In factory state a JSON write is read before the PIN check because the PIN travels in the body. The access point check also requires a client address in the access point subnet, and locking closes the session only for its holder. Refuses listing, reading, deleting and uploading the protected file, the mode record, configuration backups and temporary files. On ESP8266 the access point check uses the fixed /24 access point subnet, because that core has no subnet query. |
